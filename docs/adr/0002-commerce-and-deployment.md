# ADR-0002: Checkout, резерви та розгортання

Дата: 2026-10-05. Статус: прийнято.

Checkout працює в транзакції PostgreSQL. Advisory lock серіалізує однакові ключі ідемпотентності, блокування кошика виключає його одночасну зміну. Унікальні ключі замовлення і кошика забезпечують додатковий захист у БД. Залишки блокуються в порядку variant_id/warehouse_id; кілька складів можуть виконати одну позицію замовлення. CHECK-обмеження захищають кількість, резерв і грошові підсумки.

Стан замовлення контролює Symfony Workflow. Кожен перехід блокує рядок замовлення, змінює склад і додає історію в одній транзакції. Expiry повторно перевіряє статус після блокування, тому не скасовує вже оплачене замовлення. Два процеси в інтеграційних тестах перевіряють конкуренцію за останню одиницю та одночасний повтор одного checkout.

PaymentGateway має лише StubPaymentGateway. Дані й документація явно позначають симуляцію; дія pay дозволена лише персоналу. Публічного endpoint для підтвердження оплати немає. Доставка має локальні тестові методи з нульовою вартістю.

GraphQL використовує ті самі прикладні сервіси доступу до кошика й замовлень та окрему схему читання. Symfony/API Platform продовжує надавати Swagger UI; автоматичне GraphQL API Platform вимкнено, щоб не відкрити сутності без перевірки власника.

Production-образ не має dev-залежностей, працює як www-data і використовує php.ini-production. Конфігурація Compose вимагає явних секретів; локальні секрети виключені з build context. Окремий worker обробляє scheduler і async; оновлення виконується з коротким вікном обслуговування та прогріванням кешу.

Deptrac блокує заборонені залежності шарів. Зафіксовано вузькі винятки попередньої реалізації: RegisterUser використовує security User і UserRepository; Domain допускає компонент Uid. Це поступове зміцнення поточної архітектури, а не повна міграція всіх модулів на типізовані DTO. Універсальні записи stdClass залишаються технічним боргом.
